A private installation can now publish, sign and verify its own container images. The host executor trusted exactly one chain — images from the upstream registry, signed by the upstream publish workflow's keyless identity, with commit ancestry read from GitHub — so an installation building its own images had no supported way to verify them. A root-owned `publisher` block names the repository, the cosign public key and the compare endpoint to use instead. All three are required together: an image with no key is an unsigned image, and a key with no compare endpoint cannot prove a candidate is a forward update, so a partial block is refused rather than assumed. The key must be an absolute, root-owned, non-group-writable path, because whoever can rewrite it decides which images may run, and the keyless identity flags are not passed alongside the key, because two accepted chains would mean either could admit an image. Commit ancestry is proved in the direction that works on Forgejo, whose compare API returns a commit count rather than GitHub's `status` and `merge_base_commit`: the executor asks what is reachable from the previous image but not the candidate, and requires zero. Nothing changes for an installation tracking upstream.
