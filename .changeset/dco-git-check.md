Sign-off verification no longer depends on an API call that cannot complete. The hosted DCO check cannot evaluate a pull request of more than 250 commits: the commit list is capped there, its fallback does not finish, and it reports a failure whose message — that the commit list could not be retrieved — is indistinguishable from a genuinely missing sign-off while being the opposite of one. A large integration branch hits this every time, and nothing in the repository can fix it. A new workflow checks the same contract from the commit objects themselves, where no such limit exists: every non-merge commit must carry a sign-off whose email matches its author or its committer, merge commits are exempt because they assert no authorship, and individual remediation is honoured for a commit that cannot be rebased because its hash is pinned as provenance elsewhere. Third-party remediation stays refused, since nobody can attest to another person's authorship. The new check runs alongside the existing one under a distinct name rather than replacing it, so it can be observed passing before anything is made to depend on it, and a failure now names the offending commits and what to do about them.
