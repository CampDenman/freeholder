Public cart, checkout and order confirmation — the shopper-facing half of the C3.24 parity mapping's G2 gap (C3.25 slice 3), built on the existing C5.20–C5.22 services with no parallel money path. Product cards on `/c/<slug>`, `/search` and the product detail block gain add-to-cart (a variant picker when the product has options), quoted by one new public `catalog.purchaseOptions` projection that reads the same `resolvePrice` and `availability` the cart refreshes from. The guest's cart capability travels in an HttpOnly `fh_cart` cookie (`<cart id>.<cart token>` — the services still refuse an id without the matching token), and a new `cartWidget` chrome block renders the count and a mini-view; fresh instances get it in the default header. Public pages: `/cart` (option labels, quantity, remove, save-for-later handoff to the existing wishlist for signed-in customers), `/checkout` (contact fields resolved through `contacts.resolve`, delivery methods quoted live from `catalog.quoteShipping`, terms, the existing idempotency), and `/orders/confirm` (token-gated order summary with the existing customer-invoice pay path — hosted checkout through the configured adapter when one is live, offline instructions when the business collects manually). Naming a contact is authority, so the public `catalog.shopperCheckout` entry point proves the email first — the platform's existing customer magic link — and only then composes `checkoutCart`; a signed-in customer whose contact email matches checks out in one step. Guests read their order back through `catalog.shopperOrder`, which extends the cart-token gate to the converted cart's order and nothing wider. Checkout and confirmation are noindexed/nofollowed; cart is a noindexed utility with a canonical; chrome translates in en/fr/es/ar. The merchandising editor blocks remain with C2.24.
