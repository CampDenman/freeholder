Automations can be built, checked and published. An automation triggers on an event the platform actually emits — chosen from a real list, not typed — or on a schedule, and its steps are a mix of things modules can do and prompts written into the automation itself.

Nothing runs yet. This is the part that lets an owner draw a rule and be told, before it is ever switched on, exactly what is wrong with it: a loop with no limit, a step nothing reaches, an action that needs a customer in an automation that has none. Every problem at once, not the first one.

Publishing writes a version that never changes afterwards, so a rule that misbehaves later can still be read against the wording it actually had. Restoring an old version fills the draft rather than rewriting the history.
