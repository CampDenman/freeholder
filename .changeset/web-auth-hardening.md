Security hardening for sign-in, ads and public forms. The agent (MCP) endpoint now accepts only JSON, refuses requests from other websites unless they bring their own API key, and applies the site's cross-site protection to signed-in browser sessions; agents using API keys are unaffected. Pasted third-party ad tags run in an isolated frame that cannot read your site or anyone's sign-in, and a pasted tag on a house campaign waits for review like any other. Two-factor confirmation, theme changes and security actions only ever return you to a page on your own site. Password changes are limited per account, so one person's attempts cannot lock others out, and a password can only be changed from a signed-in browser, not with an API key. Sign-in links and newsletter confirmations are limited per email address whichever form asks for them, and repeat newsletter sign-ups no longer send a new confirmation each time. Hire requests from visitors arrive as requests you confirm (handing the item over confirms it), and a public event registration holds at most ten seats; both are limited per email address. Limits on sharing, popups, handle checks, hire requests and event registrations count visitors by the address your proxy vouches for when one is configured, and are bounded site-wide otherwise, so one visitor can never switch a feature off for everyone. The DigitalOcean droplet, Docker host-updater and playground recipes now pass the visitor's real address from Caddy and trust it; other hosts are unchanged.
