# Explicit hosted-source media approval — C3.22

Generic HTML, sitemap and RSS/Atom runs may approve up to eight additional
public file origins at creation. This permits hosted exports whose images or
files live on a separate CDN. Approval is an exact scheme/hostname/port origin;
paths, credentials, queries, fragments, private IPs and lookalike hostnames do
not widen it. The source page crawler retains its original same-origin rule.

The owner form, HTTP, MCP and generated SDK use the same `imports.start` input.
The run stores its approval and the staged media plan binds that same set.
Commit refuses a stale or expanded plan before provider I/O. Existing plans
without media-origin metadata retain their original source-only behavior.

Each used media origin receives its own fresh bounded, pinned, redirect-free
robots request outside transactions. An unverifiable response refuses the
commit; a disallow prevents reading that file. Media GETs use the same importer
user agent as the robots decision. Exact URL query identities, ordinary file
type checks/scanning, real actors, independent media/CMS permissions and atomic
media/import receipts remain enforced. Approved CDN images become local typed
blocks; off-origin page links retain their actual original URL.
