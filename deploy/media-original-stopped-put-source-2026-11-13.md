# Independently stopped original PUT applied recovery — source only

This checkpoint wires one finite positive recovery path into the existing
freshly verified human service. It is source only: no compiler, lint, parser,
database, native, systemd/host action, network or provider/account operation was
run. It does not publish the full request capability or close C1.12/C11.08.
Actual portable finishes retain their existing path without a Linux condition.

`media.reconcileStorageOperation` accepts an optional `stopDrainId`. UI, HTTP
and MCP use its existing shared person-only, step-up, permission and audit
trail. Agents cannot claim that review. The ordinary recovery form passes the
same field, with guidance in English, French, Spanish and Arabic. Root must
regenerate/qualify the actual typed SDK against the final service catalog; no
SDK parity claim is made for this source-only field addition.

A text explanation, elapsed time, readiness signal or current404 is never stop
proof. The supplied ID must resolve to the existing actual executor ledger
produced by `scripts/media-writer-drain.mjs`: the immutable original namespace,
Linux runtime instance, boot UUID, PID and process start ticks must match a
captured original process, its independently verified stop and original
admission chronology. The new SQL function independently checks the same exact
birth, process set, actual verified stop and complete physical-request runtime
inventory. The single create-only PUT must predate the namespace fence; no new
historical birth, descriptor, stop date or finish is assigned to an earlier row.

The original actor/provider intent, raw first request descriptor and nonce,
actual first return, positive ACK and all existing physical observations stay
unchanged. A stop reference is included in the immutable recovery witness.
Subsequent inventory phases resolve that exact first witness, rather than
adopting whatever newer stop record happens to exist. A released namespace may
retain its original actual stop witness; release does not resurrect that old
process or grant an old token to the current runtime.

Only affirmative applied recovery consumes the stop. A newly admitted real
read must return complete bytes, the exact original request nonce/token digest,
SHA-256, length and provider revision. Two complete agreeing provider
configuration/object/version/session or retained-generation inventories must
prove the original resource without unknown retained versions/session debt.
Then the existing review records the exact stop ID and provider evidence and
settles only the original quota token. Its original caller/requests become
reviewed `stopped` rows, with a review reference; their NULL `returned_at` and
original parent's NULL `writer_finished_at` stay NULL. An independently stopped
executor is not rewritten as an actual successful caller return.

If the actual original caller and every physical request already finished,
the original portable proof and witness remain sufficient and do not need a
stop ID. The existing active-caller native oracle remains unchanged: a manual
stopped-writer narrative without actual finishes or an exact real executor
receipt still refuses before provider requests.

This phase does not infer `not_applied`, absence or physical retirement from a
local stop. A remote accepted/in-flight PUT can outlive the local process.
Unknown provider outcomes with no affirmative original nonce remain debt.
The ordinary standalone retirement consumer still requires actual originating
finishes; consuming a completed stopped-applied review for later retirement,
failed DELETE review, multipart/session recovery, quota initialization,
cutover and remaining translated guidance are separate required dependents.
The request capability stays unpublished until their full guarded semantics
and acceptance qualify.

## Source contract and prepared controls

No model, column, FK, index, trigger or journal is added. The owned unapplied82
tail adds `freeholder_media_original_executor_stopped(uuid,uuid)` and narrows
existing original-inventory/review branches to permit only affirmative stopped
PUT recovery with exact actual executor proof. The ordinary absence branch
continues refusing missing actual finishes.

Fourteen new pure cases in
`tests/core/media-original-caller-quiescence.test.ts` are prepared/unrun:
portable actual finishes; exact independent stop without inventing returns;
retained historical stop after release; missing stop; capture/readiness/missing
verification; another boot/PID/start-tick/executor; node/legacy unbound birth;
post-capture caller/foreign namespace; post-fence mutation; foreign request
runtime/changed descriptor/post-stop request; missing/multiple/non-create-only
mutation; affirmative exact nonce/body/inventory; foreign request nonce despite
equal bytes; and retained session/version/changing-policy refusal. These
fictional proof values are pure controls, not evidence of an actual executor
stop or actual provider support.

The actual stopped-process acceptance plan remains unexecuted. It requires a
disposable owner-controlled Linux/systemd site and configured private provider,
not a fake SQL `verified` drain or a mocked kernel/provider answer:

1. Admit an actual original PUT and retain its exact request ID/token digest,
   runtime birth and intended bytes, then interrupt its original application
   process after the provider has applied those nonce-tagged bytes and before
   its logical closure has committed.
2. Use the existing real operator capture/stop/verify workflow on the original
   host. Preserve its actual boot/PID/start ticks, process/cgroup absence and
   stop receipt. Agents do not read owner secrets or stop an unselected host.
3. From a new real application runtime, sign in as the owner with fresh
   verification and use the existing recovery service/UI with the exact stop
   ID. Prove actual nonce/body/complete inventories, one original PUT total,
   immutable original dates/first return and a separately retained review.
4. Refuse another host/process generation, a portable node-only birth without
   an independent platform executor proof, another original request nonce,
   retained physical versions/sessions and a current404 outcome. Confirm no
   extra PUT/DELETE, fabricated return or first-scope membership rewrite.
5. Preserve independent actual ledger/quota/raw-byte/journal/profile/client-
   drain proof. Existing returned-caller, privacy and namespace controls remain
   unchanged and must qualify on the final candidate.

Other executor/provider/container witnesses require their own genuine adapter
and acceptance. This Linux path is an optional strong recovery seam, never a
global requirement for new fully tracked Replit or other Tier1 sites whose
actual caller finishes already provide the portable proof. Full recovery,
actual platform/account acceptance and independent security sign-off remain
open.
