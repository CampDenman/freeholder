# Actual HTTP original capture — source qualification

This is evidence for the unfinished C3.47 source increment. Migration81 is
**unjournalled**, its models/services/jobs/privacy registration are not in the
runtime registry, and the owner screen still uses the existing synchronous URL
preview. This document supplies no source-completion, provider, cutover or stable
acceptance. MASTER.md §43 remains the status authority.

The source draft keeps four normalized stores: the actual selected source and
generation, original request frontier, each actual HTTP response and private
physical binding, and exact original privacy-request membership. It does not
manufacture an upload, concatenated export, WordPress identity for HTML, historical
namespace or reader identity. Public-source bodies stay in private storage; SQL
keeps minimal HTTP facts and digests. Reads use the verified physical key returned
by the shared original-object resolver while logical identities remain unchanged.

Each capture performs short authorized claim/admission/apply transactions around
one actual pinned GET and private tracked PUT. Original robots bytes and the next
network body share the 20MB phase budget; requests are paced and current caller
permission is checked again after waiting. Actual robots404 error bytes remain
captured without becoming a robots policy. Uncertain physical outcomes remain
recovery debt; neither time nor object absence authorizes refetch or replacement.
Discovery commits at most500 frontier targets per window. The synchronous sitemap
and feed parsers keep their500-entry default; durable feed discovery extracts
actual links/publication metadata without treating excerpts as rendered pages.

The unregistered privacy draft separates reader erasure membership from the
operator's identity and physical-operation ownership. Opaque text is not disclosed
as a person's export on the strength of a mailbox or operator account. Actual
privacy transactions retire affected original windows and record exact response
membership. Named holds protect only their then-existing original responses.
Actual SYSTEM services admit bounded cleanup and original-receipt reopening after
committed physical facts; durable continuation and periodic jobs cover missed
callbacks. Cancellation/expiry revoke reuse while preserving holds and unresolved
physical facts. Metadata minimization requires original-byte retirement, retaining
the opaque key/digest/namespace and operator witness for later positives. These
privacy/retirement paths are **typed and linted, but not yet natively qualified**.
