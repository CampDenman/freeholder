# Uploaded source index privacy: source checkpoint

C1.08/C3.47/C11.14 remain open. This is an unqualified source checkpoint,
not native evidence or independent security review. It composes the root
published-main containment with unpublished schema81 after the preserved
436 media-key checkpoint. SQL0–80 and the migration journal are unchanged.
No database has been migrated or reset for this change.

The actual original `f1b5d6a3` 501-WXR full-erasure oracle remains byte-identical.
Its completed raw deletion with retained normalized metadata was reproduced on
protected main81271622, independently inspected and preserved by root. A zero
query-marker count in WXR media keys does not prove keys are private-free:
actual catalog keys contain host/path. New catalog inserts therefore use the
already-owned `source_key_digest`; no second column or historical backfill.

Three private models record the first verified fulfillment's complete original
scope (including empty), run/upload membership bound to an actual retained
revision/graph generation when present, and original chunk key digests. Immutable
SQL capture guards and a deferred exact-set check reject missing/later scope.
These are erasure witnesses, separate from legal-retention snapshots.

A short private preparation phase checks the actual durable task and pending
verified artifact before physical deletion. A separate completion transaction
rechecks the same task and scope, canonical holds and physical receipts, then
minimizes eligible unaccepted projections and calls the shared core ACK under
the same transaction. The deferred completion trigger independently verifies
all captured originals and minimized graph/root copies. Intermediate tasks may
finish while other actual pending tasks still own remaining chunks; the whole
receipt cannot complete early. No provider I/O occurs in a service transaction.

Reduction preserves normalized IDs, byte ranges, SHA digests, source revision,
graph generation, cursor progress and actual ownership. WXR cursor headers were
inspected: they contain only range/SHA facts, not title/URL/body copies. Private
entry metadata, header/catalog metadata, media plans/keys/errors, unaccepted
root preview/origin/report/reader-site copies and original source filename are
minimized after physical retirement. A redacted graph remains readable without
parsing a removed private media plan.

Known held generations are retained with their exact canonical membership.
Unknown hold captures, absent first-erasure capture, substituted upload/revision,
accepted plans/batches/assets, unresolved file receipts and missing initial media
key digest refuse cleanup/completion. Old jobs never adopt a current graph.
An upload already captured for unheld erasure cannot initialize a later index.
Historical false-completed receipts need explicit original-evidence recovery;
this checkpoint does not manufacture their missing initial capture.

Required qualification: full current80 bank/finisher source composition, full
TypeScript/lint and affected contracts, NEW SQL81 hash and NEW ordinary0–81
database, 12-model parity and enabled-guard checks, unchanged original WXR and
media-URL AFTER controls, actual held/accepted/later-generation refusals,
old-image/populated upgrade and historical recovery, public API/MCP/SDK plus
four-locale production browser journeys. The three new private models still
need composition into the runtime activation's table/search/retention inventory
in the same future normal81 candidate. No stable readiness is claimed.
