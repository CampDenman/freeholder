# Genuine unattempted original DELETE continuation — source only

This finite source continuation descends from frozen76e2b230. No CPU source
checks, parser, database, native or provider action was run. The four original
functions/two triggers from that checkpoint keep their identities; no model,
column, public service, journal or capability is added. Root owns SQL assembly
and qualification. All stable and provider acceptance remains open.

A preflight full-byte or inventory refusal can occur before the newly admitted
logical DELETE has made any physical provider request. Its actual owning
closure then retains `notAttempted` and its real finish. The first checkpoint
conservatively left a present object pending after that closure. This slice
permits a later cleanup invocation to commit a separate new receipt/caller,
with a new server-held token, only when every earlier DELETE is genuinely
unattempted. It never restarts an old admission, changes its first return or
turns elapsed time into authority.

The common pure rule requires an actual returned logical caller, its immutable
`notAttempted` result digest, no positive ACK, and either no physical request or
one actually finished request with only the authentic `not_attempted` fact.
A response, body, metadata or accepted fact contradicts that classification.
Unknown/paused callers, missing physical finishes, corrupt descriptors and
ambiguous provider failures remain pending. An actual acknowledged DELETE
permits fresh verification only. Multiple real dispatches are recovery debt.

The shared producer uses that rule before committing another caller and again
at physical request admission. The SQL request guard independently rejects any
earlier receipt that lacks the same exact unattempted proof. The complete
retirement predicate now covers the one original PUT and all of its separately
born DELETE intents, allowing at most one actual accepted physical dispatch.
After the existing fresh pinned absence and complete physical version/session
inventory proof, prior genuinely unattempted receipts can become
`confirmed_absent`; none gain a fabricated ACK or replacement first return.
Quota and minimization still follow the exact original UUID/token family.

A physical request whose real job gate refused I/O carries the existing
`TransferRequestNotAttemptedError`. The owning closure now retains its actual
`notAttempted` result rather than misclassifying that genuine refusal as an
ambiguous write. No generic provider exception is caught as unattempted.
