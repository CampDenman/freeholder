The current shared signUploadParts orchestrator now admits each new signing
attempt through its actual owning short claim service, original process-held
invocation, server-resolved principal and immutable original body declaration.
Every attempt has a separate media_multipart_operations row (new kind `sign`),
a genuine same-transaction multipart_sign caller and a once-only multipart.sign
request nonce. A nullable/no-default/no-backfill JSONB `part_issue` column on
the existing operation model binds the exact body-manifest ID/digest, part
number, SHA256, bytes and intended deadline. The original provider session is
captured in the existing immutable operation provider_upload_id. No new table,
contact FK or module-private owner is created; the original resource supplies
all ownership, merge, retention and immutable-first-erasure ancestry.

The configured managed S3 facade accepts the real observer and live genuine
issuer scope only. Generic flags, a raw facade reference, another original
caller or a different part/session/body cannot reach the local SDK signer.
The new script uses the existing actual aws4fetch signer outside transactions,
with allHeaders:true. It binds Content-Length, SHA256 checksum, payload SHA and
a public original physical request-ID header into SigV4. The raw server-held
caller/request tokens never enter the URL, browser headers or retained proof.
It verifies the actual returned method, host, path, session, part, signature
headers, deadline and header values before returning any capability. Duplicate
or foreign query parameters and wider/different signed results refuse. The
browser sends the exact returned signed headers with its original Blob; its
Content-Length is generated from that Blob by the browser. Actual provider
acceptance, browser/CORS behavior and checksum/size enforcement remain external
qualification obligations, not claims made by local cryptographic tests.

The actual signed result is recorded as a distinct local `capability` fact,
including immutable URL/header digests, public physical nonce, body/session
identity and actual signed deadline. It is **not** a provider response, upload
ACK, actual received-body SHA, part finish or URL consumption. Both physical
and logical local FINs are authenticated by their original token and retained
before the owning service can return its URL to the client. The actual machine
principal is checked at physical mint admission and successful result retention;
a revoked/expired credential cannot acquire a later returned grant. Positive
facts and machine FIN can still be retained after failure/revocation without
returning the bearer capability. Every sibling attempt drains through
allSettled before the owning invocation closes, including when another attempt
fails. An admission refused before local dispatch can retain a genuinely
unattempted first return; an unknown attempt is never replayed or overwritten.

The provider/caller/request ledgers retain every issued, failed, unknown and
late original attempt. The current parent-scoped privacy exporter, evidence
version/outbox and erasure checks already enumerate every operation and caller
through exact original resource FKs, so a later actual local fact stays on that
same original lineage. It cannot become an unrelated later generation or refill
a first erasure capture. A late mint reopens its original resource debt; no key,
owner, birth or FIN is reconstructed from current scope. No raw bearer URL is
stored. Existing scoped minimization still requires all original physical
copies/session authorities to retire before minimizing their private evidence.
